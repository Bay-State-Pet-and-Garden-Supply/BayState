## 2. Current Architecture Summary

**Monorepo:** Bun 1.3.5 + Turbo 2.8.17. Three workspaces: `apps/web` (Next.js 16), `apps/scraper` (Python/Playwright), `packages/api` (shared tRPC lib).

**Web app:** Next.js 16 App Router. `(storefront)` for customer pages, `admin/` for 26-module admin dashboard. Supabase for auth/DB/realtime. Stripe for payments. Tailwind v4 + shadcn/ui.

**Auth:** Supabase Auth via `@supabase/ssr`. Server components use `createClient()` from `lib/supabase/server.ts` (cookies-based SSR). Client components use `createBrowserClient()`. No middleware.ts for auth — auth checks at layout level.

**DB:** 175 migrations in `supabase/migrations/`. Public schema. RLS enforced. Migrations are timestamped (`YYYYMMDDHHMMSS_description.sql`). Seed data is missing.

**Payments:** Stripe PaymentIntents with automatic payment methods. Client-side `stripe.confirmPayment()` via Stripe Elements. Webhook handler at `/api/payments/webhook` updates `orders.payment_status`. Stripe SDK pinned to `2025-12-15.clover` API version.

**Scraper integration:** Web coordinator queues jobs, scraper polls via `/api/scraper/v1/poll`, posts results back. Webhook-style callback ingestion in `lib/scraper-callback/`.

## 3. Current Payment Flow (text diagram)

```
CUSTOMER                          BROWSER                          SERVER                           STRIPE
───────                          ───────                          ──────                           ──────

1. Add items to cart               Zustand cart store
   (persisted localStorage)

2. Go to /checkout                 CheckoutClient renders
   (3-step wizard)                 contact→fulfillment→payment

3. Click "Review & Pay"            handlePlaceOrder()
                                   ├─ POST /api/orders ──────────► createOrder()
                                   │  (creates row in `orders`,    ├─ INSERT orders
                                   │   status=authorized,          ├─ INSERT order_items
                                   │   payment_status=authorized)  └─ sendOrderConfirmationEmail()
                                   │
                                   ├─ POST /api/payments/intent ──► createPaymentIntent()
                                   │  (amount from client total,   ├─ stripe.paymentIntents.create()
                                   │   NO server-side verify)      │  ─────────────────────────────► PaymentIntent created
                                   │                               │◄─ {client_secret, id} ────
                                   ◄─ {clientSecret} ──────────────┤

4. See PaymentElement              PaymentForm renders
   (Stripe Elements)               Stripe Elements mounts

5. Enter card details              stripe.confirmPayment()
   & submit                        ──────────────────────────────────────────────────────────────────► PaymentIntent confirmed
                                                                                                     ◄─ {status: 'succeeded'}

6. Client marks order paid         handlePaymentSuccess()
                                   ├─ POST /api/orders/:id/
                                   │  payment-complete ───────────► update orders.payment_status='paid'
                                   │                               ├─ INSERT order_events
                                   │                               └─ retrievePaymentIntent (verify)
                                   │
                                   └─ router.push(/order-confirmation/:id)

INDEPENDENTLY (async):

Stripe webhook                     ─────────────────────────────────────────────────────────────────────► POST /api/payments/webhook
                                                                                                        ├─ constructWebhookEvent (verify sig)
                                                                                                        ├─ payment_intent.succeeded:
                                                                                                        │  ├─ updateOrderPaymentStatus→'paid'
                                                                                                        │  ├─ recordPaymentTransaction → INSERT order_payments
                                                                                                        │  └─ INSERT order_events
                                                                                                        │  ⚠️ NO idempotency check (stripe_event_id not stored)
                                                                                                        │  ⚠️ Duplicate webhook = duplicate order_payments row
                                                                                                        ├─ payment_intent.payment_failed:
                                                                                                        │  └─ updateOrderPaymentStatus→'failed'
                                                                                                        └─ charge.refunded:
                                                                                                           ├─ updateOrderPaymentStatus→'refunded'|'partially_refunded'
                                                                                                           └─ INSERT order_payments (refund row)
```

**Key observations:**
- Dual-write pattern: both client-side (`payment-complete`) and webhook update payment status — creates race condition risk
- No Stripe event idempotency: webhook re-delivery inserts duplicate `order_payments` rows
- Client-authoritative amount: `/api/payments/intent` trusts client `amount` without server-side verification against DB order
- No duplicate PaymentIntent guard: refreshing checkout can create multiple PIs for same order

## 6. Concrete Constraints

### Tech stack (locked)
- **Runtime:** Bun 1.3.5 (package manager + dev/prod), Node.js 18+ (fallback)
- **Framework:** Next.js 16 App Router (TypeScript strict)
- **DB:** Supabase (Postgres 17 locally, hosted on Supabase platform)
- **Auth:** Supabase Auth (`@supabase/ssr`), no middleware.ts for auth
- **Payments:** Stripe SDK `^20.2.0`, `@stripe/react-stripe-js` + `@stripe/stripe-js`
- **Styling:** Tailwind v4 (CSS-based, no tailwind.config.js), shadcn/ui
- **State:** Zustand (cart), React Hook Form + Zod (forms)
- **Tables:** `@tanstack/react-table` with server-side filter/paginate
- **Monorepo:** Turbo 2.8.17, workspaces: `packages/*`, `apps/*`
- **CI:** `bun install --frozen-lockfile` → `bun run lint` → `bun run test`

### Patterns to follow
- **Imports:** `@/*` absolute paths, named exports only
- **Supabase:** `createClient()` from `lib/supabase/server.ts` (SSR) or `client.ts` (browser)
- **API routes:** `route.ts` exports (GET, POST, etc.), Zod validation, `NextResponse.json()`
- **Server Actions:** Zod schema → DB mutation → `revalidatePath()`
- **Components:** kebab-case files, PascalCase exports, `"use client"` for interactive
- **Migrations:** `YYYYMMDDHHMMSS_description.sql`, never edit applied migrations

### Anti-patterns (DO NOT)
- No `any`, `@ts-ignore`, `@ts-expect-error`, default exports
- No direct DB access from client components (Server Actions or API routes)
- No middleware.ts for auth (auth at layout level)
- No bypassing RLS
- No `eslint-disable` comments
- No `request.json()` for Stripe webhook handler (must use `request.text()`)
