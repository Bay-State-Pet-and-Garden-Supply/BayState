# Seed Fix Report

## Summary
Fixed `supabase/seed.sql` so that `supabase db reset` passes.

## Initial Error
```
failed to send batch: ERROR: syntax error at or near "ON" (SQLSTATE 42601)
```

## Root Cause
The seed file had several conflicts with migration-seeded data:
- Migrations insert `pet_types` with auto-generated UUIDs and a unique constraint on `name`; the seed tried to insert the same names with explicit UUIDs using `ON CONFLICT (id) DO NOTHING`, which didn't catch the name constraint violation.
- Migrations insert `categories` with slugs like `dog-food`, `dog-treats-chews`, etc.; the seed tried to insert the same slugs with explicit UUIDs.
- Migrations insert `facet_definitions` with slugs like `animal-type`, `life-stage`, etc.; the seed tried to insert the same slugs.
- `facet_values` hardcoded `facet_definition_id` UUIDs that might not exist if the `facet_definitions` INSERT was skipped.

## Fixes Applied

### 1. Pet Types — ON CONFLICT target change
**Changed**: `ON CONFLICT (id) DO NOTHING` → `ON CONFLICT (name) DO UPDATE SET id = EXCLUDED.id`
**Why**: Migration inserts pet_types with auto-generated UUIDs and a unique constraint on `name`. The seed's explicit UUIDs replace the auto-generated ones, ensuring `product_pet_types` foreign key references work.

### 2. Categories — ON CONFLICT target change
**Changed**: `ON CONFLICT (id) DO NOTHING` → `ON CONFLICT (slug) DO NOTHING`
**Why**: Migration inserts L2 categories with the same slugs. Using `ON CONFLICT (slug)` correctly catches the conflict instead of erroring.

### 3. Product Categories — UUID resolution change
**Changed**: Hardcoded category UUIDs → `(SELECT id FROM categories WHERE slug = '...')` subqueries
**Why**: Since the seed's category explicit UUIDs may not be used (ON CONFLICT skips), look up the actual category ID by slug at insert time.

### 4. Facet Definitions — ON CONFLICT target change
**Changed**: `ON CONFLICT (id) DO NOTHING` → `ON CONFLICT (slug) DO NOTHING`
**Why**: Migration inserts facet_definitions with the same slugs. Using `ON CONFLICT (slug)` correctly catches the conflict.

### 5. Facet Values — UUID resolution change  
**Changed**: Hardcoded `facet_definition_id` UUIDs + `VALUES` clause → `SELECT * FROM (VALUES ...)` with `(SELECT id FROM facet_definitions WHERE slug = '...')` subqueries
**Why**: Since facet_definition explicit UUIDs may not be used, look up the actual ID by slug at insert time.
