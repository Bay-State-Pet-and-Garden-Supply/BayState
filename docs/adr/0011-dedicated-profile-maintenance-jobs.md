# Dedicated profile-maintenance jobs

The web coordinator and scraper runners use dedicated profile-maintenance jobs for Brand Source Setup and Site Extraction Profile work instead of overloading product `enrichment_jobs`. These jobs reuse the existing runner lease/callback pattern, but are scoped to brand, Source, canonical domain, Browser Profile, Site Extraction Profile, or Profile Version rather than UPC/product extraction attempts.

Initial job kinds include `verify_pdp_seed`, `draft_site_extraction_profile`, `validate_profile_version`, `browser_profile_setup`, and `browser_profile_revalidate`. Each job declares required runner capabilities so claim logic can route work to runners with suitable Crawl4AI, model, Browser Profile, or interactive-browser support. Jobs produce versioned durable maintenance artifacts rather than storing review evidence only as logs or blob JSON on the job row. Each artifact uses a shared envelope for scope, provenance, status, and schema version, plus a typed payload for the specific artifact kind. Artifact evidence is immutable once created; retries, corrections, or regenerated evidence create new artifact versions while review metadata may change. Bulky evidence such as screenshots, HTML/markdown snapshots, crawl traces, and large Image Candidate dumps lives in object storage with durable references from the artifact record and is retained by default with explicit retention and purge controls. Maintenance artifacts exclude secrets and identity state such as cookies, storage contents, auth headers, Browser Profile files, and raw token-bearing request headers. These artifacts do not directly advance or fail product pipeline status. Product enrichment jobs consume only approved active profile snapshots and validated Browser Profile references.
